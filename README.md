# GO Fitness Mobile

تطبيق Flutter مخصص لنظام GO Fitness، بواجهة RTL عربية وهوية بصرية مطابقة لتطبيق الويب (أسود `#151515` وأصفر أساسي `#FFCC00`). يستخدم شعار GO الأصلي من `assets/go-fitness-emblem.png` داخل التطبيق وفي أيقونات Android وiOS والويب، ويعتمد على Material 3 مع `flex_color_scheme`.

## التشغيل

```bash
flutter pub get
flutter run
```

رابط الإنتاج الافتراضي مضمّن بأمان (لا يحتوي أسرارًا):
`https://gosystem.onrender.com/api/v1`. يمكن استبداله لبيئة اختبار عبر
`--dart-define=API_BASE_URL=https://your-api-host/api/v1`، أو تمرير قيمة فارغة
لتشغيل وضع العرض التجريبي.

للتشغيل على Android Emulator مع backend يعمل على نفس جهاز التطوير:

```bash
flutter run --dart-define=API_BASE_URL=http://10.0.2.2:8080/api/v1
```

يستخدم التطبيق عقد الإنتاج الحقيقي، ومن أهم المسارات:

- `POST /auth/staff/password/sign-ins` أو `POST /auth/member/password/sign-ins`
- `GET /organizations/{organizationId}/dashboard/summary?branchId=...&from=...&to=...`
- `GET /me/account-notifications?limit=30`
- `GET /self` ومسارات `/self/organizations/...` لبوابة العضو وولي الأمر
- `GET/PATCH /self/account` و`POST /self/account/password-changes`
- مسارات الطلبات والمدفوعات والحجوزات والاشتراكات وCRM والمالية والتقارير والتشغيل

يتم حفظ access/refresh tokens ونوع الجلسة في `flutter_secure_storage` مع تجديد تلقائي للجلسة. تعرض إشعارات صندوق الحساب داخل التطبيق وتصدر تنبيهًا نظاميًا عند وصول رسالة جديدة أثناء عمل التطبيق. الإشعار الخارجي الحقيقي في الخلفية يتطلب إعداد مشروع FCM/APNs وبيانات اعتماده وإضافة device-token endpoint إلى الـbackend؛ هذه المدخلات غير موجودة حاليًا في المستودعين ولذلك لم تُضمّن مفاتيح وهمية أو غير آمنة.

## ما تم بناؤه

- تسجيل دخول الموظف أو العضو بتصميم متجاوب.
- لوحة مؤشرات: الأعضاء، الاشتراكات، الدخول، الإيرادات، مخطط 30 يومًا من بيانات التقرير الحقيقية، إجراءات سريعة وتنبيهات تشغيلية.
- دليل أعضاء مع بحث وحالات العضوية ونموذج تسجيل عضو فعلي مطابق لعقد الـAPI.
- مركز تشغيل للحضور والحجوزات ونقطة البيع والمطعم وجدول اليوم، مع تسجيل دخول عضو فعلي.
- صندوق رسائل وإشعارات مع عداد غير المقروء وتحديد الكل كمقروء.
- تنقل هرمي مطابق لنسخة الويب: «إدارة النادي»، «الأعمال»، و«الإدارة»، مع مساحات مترابطة لنقطة البيع والمالية وCRM والتواصل والمطعم والتدريب والموظفين، ومصفاة حسب صلاحيات الحساب والفرع.
- مركز «إعداد النظام» كامل بمجموعاته الداخلية: النادي والموظفون، الصلاحيات، الخدمات والتسعير، المرافق والتشغيل، التدريب، المطعم، المتجر والمخزون، المالية والتواصل.
- مساحة «البوابات والبصمة» تجمع حالة لوحات ZKTeco، الاتصال والمراقبة، مؤشرات القبول والمراجعة، سجل المرور، التصفية حسب البوابة، وقرار الجهاز وقرار GO في شاشة مهيأة للموبايل وتتحدث دوريًا.
- أكثر من 80 مساحة قراءة مترابطة و89 عملية موبايل موجهة، تشمل الطلبات والمدفوعات والاستردادات والصندوق والكتالوج والباقات والأسعار والعروض والمرافق والمطعم والمتجر والمخزون والقياسات والدوام والبوابات والخزائن والملفات والحملات والمستخدمين والأدوار.
- نقطة بيع مخصصة للموبايل تجمع بيع العضويات والخدمات والمنتجات وطلبات المطعم، والتحصيل ببطاقة أو تحويل أو نقد أو بوابة دفع أو محفظة، والتحصيل المقسّم، وفتح وردية الصندوق وإغلاقها، مع الطلبات والفواتير والمدفوعات في مساحة واحدة.
- نماذج موبايل فعلية للاشتراك والدفع والحجز وCRM والمصروف والإيراد والمناوبة والمطعم والموظف والقياسات وتحديث التقارير.
- إجراءات على السجلات للتجميد والاستئناف والإلغاء، إلغاء التجميد المجدول، إضافة أيام أو زيارات وتغيير بداية الاشتراك، إكمال الحجوزات، تجهيز وتسليم طلبات المطعم، مراحل CRM، اعتماد المصروفات، وطلبات الانضمام.
- تفاصيل مترابطة من بطاقة السجل: كشف وردية الصندوق، قواعد ومواعيد مورد الحجز، جدول المدرب والأعضاء المسندون، وتفاصيل الفاتورة والحجز والقياس.
- مركز تواصل يدعم نفس جماهير Next (عضو أو عميل محدد، شرائح، أو الجميع) مع معاينة عدد المستلمين قبل الإرسال، وفحص جاهزية مزود واتساب قبل إنشاء الحملة.
- تفاصيل عضو مترابطة مع ملفه المالي والتشغيلي، وإصدار رمز التفعيل وإعادة تعيين كلمة المرور والحظر.
- بوابة مستقلة للعضو/ولي الأمر تعرض الاشتراكات والحضور والحجوزات والخطط التدريبية التفاعلية والقياسات والطلبات والفواتير والملفات والتواصل، مع شراء الباقات وتجديد الاشتراك وجدولة التجميد وطلب وجبات قائمة اليوم وتفعيل الحساب لأول مرة.
- مساحة عمل ذاتية للموظف والمدرب تشمل الملف والمناوبات والحضور، وأعضاء المدرب وجدوله وخطط التدريب والقياسات والعمولات.
- مساحة ملفات أصلية للموبايل: اختيار JPG/PNG/PDF، حساب SHA-256 محليًا، signed upload إلى التخزين الخاص، إكمال الفحص الأمني، وتنزيل الرابط الموقّع فقط للملفات النظيفة.
- بحث شامل سريع للموظفين عن الأعضاء والموظفين والاشتراكات والفواتير، مع فتح السجل المقصود من النتيجة.
- مسح باركود العضوية بالكاميرا لتسجيل الحضور؛ تتم مطابقة الرمز محليًا بقائمة أعضاء الفرع ثم تُرسل محاولة الدخول إلى `/attendance-attempts`.
- تبديل المؤسسة والفرع مع حفظ السياق، وإعدادات الحساب واللغة والتوقيت والتنبيهات وكلمة المرور.
- الوضع الداكن، RTL، touch targets مناسبة، pull-to-refresh، وحالات العرض التجريبي/الاتصال الحقيقي.

## التحقق والبناء

أوامر التحقق المحلية:

```bash
flutter analyze
flutter test
flutter build web --release
flutter build apk --debug
```

ملفات Android الناتجة موجودة في `build/app/outputs/flutter-apk/`، ونسخة
المعاينة تتصل افتراضيًا بخادم Render. هوية الحزمة هي
`com.gofitness.app` ويدعم Android API 24 فما فوق، مع `targetSdkVersion 36`.

آخر تحقق حي على خادم Render شمل 13 مجموعة كتابة للموظف و5 مجموعات لبوابة
العضو (ومنها شراء ورفع ملف حقيقي)، ونجحت جميعها. التفاصيل في
`docs/feature-parity.md`.

تحتاج ميزة الملفات إلى صلاحية اختيار الملفات، وتحتاج ميزة مسح الباركود إلى صلاحية الكاميرا (تمت إضافة الوصف العربي في Android وiOS). الحزم الأصلية المستخدمة هي `file_picker` و`mobile_scanner` و`url_launcher` و`crypto`.

## المعاينة على الأجهزة

للمعاينة السريعة في Chrome بمقاس هاتف:

```bash
flutter run -d chrome --web-port 50550
```

للمعاينة على Android، شغّل Emulator من Android Studio أو صِل هاتفًا مع USB debugging، ثم:

```bash
flutter devices
flutter run -d <android-device-id>
```

وللتثبيت المباشر لنسخة المعاينة الحالية:

```bash
adb install -r build/app/outputs/flutter-apk/app-debug.apk
```

ولإنشاء نسخة Release بعد إعداد توقيع Android استخدم
`flutter build appbundle --release` للنشر أو `flutter build apk --release`
للتثبيت المباشر.

راجع [مراجعة تكافؤ الميزات](docs/feature-parity.md) و[قائمة جاهزية
المتاجر](docs/store-release-checklist.md) قبل أي إصدار عام.

يلزم macOS لبناء iOS. بعد تثبيت Xcode وCocoaPods وفتح المشروع على Mac:

```bash
flutter pub get
cd ios
pod install
cd ..
open ios/Runner.xcworkspace
flutter devices
flutter run -d <ios-device-id>
```

اختر Apple Team وBundle Identifier من Signing & Capabilities داخل Xcode. ولإنشاء ملف توزيع بعد إعداد الشهادات:

```bash
flutter build ipa --release
```
